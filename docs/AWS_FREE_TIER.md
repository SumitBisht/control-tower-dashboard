# AWS free-tier deployment

> **Status:** the Terraform here has **not been applied or `terraform validate`d** by its author (no AWS/Atlas access), only
> syntax-checked. Review `terraform plan` before applying. The Docker compose file was validated locally.

Runs the whole app on **one small EC2 server + a free MongoDB Atlas M0 cluster**, about US$0/month while within free limits.
For a production-grade (but ~US$135/month) layout see [AWS_DEPLOYMENT.md](AWS_DEPLOYMENT.md).

```
Browser ─HTTPS─▶ EC2 t3.micro ── Docker: Caddy (auto HTTPS) → nginx (React) → FastAPI ──▶ Atlas M0 (512 MB, free)
                      └── Elastic IP, 30 GB disk, IAM role ──▶ S3 (reports + photos)
```

## Check free-tier terms first (they changed in 2025)
- Accounts created **before mid-July 2025**: 12 months of 750 h/month of `t2/t3.micro`, 30 GB EBS, 5 GB S3 (and the public IPv4 hour allowance).
- Accounts created **after**: a credit-based free plan (credits + a trial period) - confirm at <https://aws.amazon.com/free>.
- Atlas **M0 is free indefinitely** but limited: 512 MB storage, no automatic backups, not offered in every region.
- Create an **AWS Budget alert (e.g. US$5)** before anything else. Anything left running outside the free allowance is billed.
- Elastic IPs are only free while attached to a running instance.

## What fits and what doesn't
| Item | Free-tier reality |
|---|---|
| Data | Reports store *data* in Mongo (small: a 25-container report is a few hundred KB) - 512 MB holds many reports. Photos and the original `.docx` go to S3/disk, not Mongo. |
| Files | 5 GB S3 free ≈ 50 reports of ~100 MB. Beyond that, S3 costs ~US$0.025/GB-month. |
| Memory | `t3.micro` has 1 GB. The setup adds 2 GB swap; image builds are slow (minutes) but work. Use `t3.small` (set `instance_type`) if your account has credits and uploads of ~100 MB feel slow or get killed. |
| Availability / backups | Single server, no redundancy. Take EBS snapshots; export Atlas data occasionally (`mongodump`). |

## Prerequisites
- AWS CLI configured (`aws configure`), Terraform ≥ 1.6, Git Bash/WSL (for `deploy.sh`), `ssh`/`tar`.
- An EC2 **key pair** in your region (EC2 console → Key Pairs → create, download the `.pem`).
- Atlas **organization ID** + organization **API key** (Organization Access Manager → API Keys, role *Organization Project Creator*):
  ```bash
  export MONGODB_ATLAS_PUBLIC_KEY=...  MONGODB_ATLAS_PRIVATE_KEY=...
  ```
- Your public IP (for SSH), e.g. from <https://checkip.amazonaws.com>.

## Deploy
```bash
cd infra/terraform-free
cp terraform.tfvars.example terraform.tfvars     # set atlas_org_id, key_name, ssh_cidr, admin_email, client_name
terraform init
terraform apply                                  # ~5 min (Atlas M0 + EC2 + Elastic IP + S3)
cd ../..
infra/terraform-free/deploy.sh /path/to/my-key.pem   # waits for first boot, copies the code, builds and starts it
```
Then open `terraform output site_url` (an `https://<ip-with-dashes>.sslip.io` address unless you set `domain`).
Sign in as `admin_email`; get the generated password with:
```bash
terraform -chdir=infra/terraform-free output -raw admin_password
```
Create real users under **Users**, then change/disable the seeded admin if you like.

**Custom domain:** set `domain = "control.example.com"` and create an `A` record pointing to the Elastic IP *before* the first
`deploy.sh` (Caddy needs it to obtain the certificate).

## Updating the app
Re-run `infra/terraform-free/deploy.sh /path/to/key.pem` - it re-uploads the code (keeping the server's `.env` files) and rebuilds.
Change `CLIENT_NAME` etc. by editing `/opt/control-tower/backend/.env` on the server, then
`docker compose -f docker-compose.free.yml up -d --force-recreate backend`.

## Troubleshooting
| Symptom | Check |
|---|---|
| `deploy.sh` says server not ready | `ssh` in, `sudo cat /var/log/control-tower-bootstrap.log` |
| Site not reachable / no certificate | DNS points at the Elastic IP; ports 80/443 open; `docker compose -f docker-compose.free.yml logs caddy` |
| API errors about the database | Atlas → Network Access contains the Elastic IP; `docker compose ... logs backend` |
| Build killed / very slow | Swap active (`free -m`); try `t3.small` |
| Uploads fail to save | Instance role + bucket exist; `docker compose ... logs backend` (S3 access denied?) |
| Atlas M0 rejected in your region | Pick a region where M0 is offered and set `atlas_region` (and ideally `aws_region`) |

## Security notes
- Secrets are generated by Terraform, written to `/opt/control-tower/**/.env` (mode 600) via EC2 user-data, and are present in the
  Terraform state - keep `terraform.tfstate` private (it is git-ignored). Use SSM Parameter Store/Secrets Manager if you outgrow this.
- SSH is limited to `ssh_cidr`; update it (and re-apply) if your IP changes.
- HTTPS is automatic (Let's Encrypt via Caddy). Consider turning `ALLOW_SELF_REGISTRATION` off once your users exist.
- Instance metadata requires IMDSv2 (hop limit 2 so containers can use the S3 role).

## Teardown
`terraform -chdir=infra/terraform-free destroy` (empty the S3 bucket first). This deletes the Atlas cluster and all its data.
